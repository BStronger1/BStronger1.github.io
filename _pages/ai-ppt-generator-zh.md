**AI 产品 · 2026 年 10 月**

AI PPT生成将项目材料转化为可编辑的演示文稿。它先根据目标受众规划叙事方式，再生成页面目标、证据、视觉结构和原生 PPTX。学术汇报可以从研究问题切入，管理汇报可以先提出决策，入门教学则可以从熟悉的情境开始。

**技术栈：** React / TypeScript · FastAPI · PostgreSQL · Redis / ARQ · LangGraph · python-pptx

## 工作流程

选择受众、先验知识、时长和目标 → 上传或粘贴材料 → 审查 AI 叙事规划与大纲证据 → 生成并编辑幻灯片 → 导出包含演讲备注的可编辑 PPTX。

## 产品功能

* **个人模型设置：** 选择 OpenAI 兼容模型，获取可用模型列表，测试连接，并使用按账号加密保存的 API 密钥。所选模型用于大纲、幻灯片、AI 编辑和重新排版。
* **面向受众的叙事：** 六类预设覆盖学术评审、管理者、技术同行、投资 / 商业评审、入门教学和自定义受众。用户输入的先验知识与指令优先于预设假设。
* **可解释规划：** 生成幻灯片前展示建议开场、叙事阶段、结尾行动、理由与假设。以认知负荷、多媒体学习和精加工原则作为设计参考；AI 规划失败时明确标注预设回退。
* **页面设计与演讲：** 分配页面角色、过渡和讲述时长，根据内容使用对比、流程、证据或观点布局；保留有意义的留白，并将叙事指导导出到演讲备注。
* **大纲证据审查：** 为各个大纲要点附加来源引用和摘录，校验摘录是否存在于所提供的材料中，并标记无效引用与被修改的陈述以供审查。
* **编辑流程中的证据：** 提供来源查看和补充材料入口，并在导出的演讲备注中保留大纲引用。
* **审慎处理材料缺口：** 在答辩场景中允许简短内容和明确的证据缺口，不自动扩写稀疏材料以满足密度目标。
* **部署与验证：** 在隔离的 Linux 用户环境中运行 API、工作进程、PostgreSQL 和 Redis，配置持久化存储、进程守护与启动项。

## 已验证内容

**2026 年 10 月 4 日**，服务器验收上传了一个虚构文本文件，通过配置的模型 API 生成六页大纲与六张幻灯片，导出 **52,400 字节的 PPTX**。随后重新读取文件，确认每页包含可编辑文本与大纲来源备注。

重启应用的四项服务后，六条幻灯片记录仍为就绪状态，上传文件的 SHA-256 与原文件一致。已安装启动项并测试启动脚本，但未重启共享服务器本身。

最近一次本地后端回归测试报告为 **416 项通过、3 项跳过**。另外两次真实模型运行对同一虚构材料分别使用管理者与入门教学受众，两者都生成了 AI 叙事规划、300 秒时长分配和六张可编辑幻灯片。管理版开场提出决策，教学版以丢失钱包的情境开场并以练习结束。这些检查覆盖软件行为，不代表已经测得幻觉减少或用户效率提升。

## 功能边界

证据关联到**大纲要点**，并非每一句生成文本。摘录匹配仅检查原文是否存在，不能证明来源支持对应陈述。生成正文与手动编辑仍需审查。本版本未实现 OCR、检索增强生成或自动语义事实核查。

受众预设是可编辑的产品假设，不是心理画像。尚未通过受众研究验证理解、记忆或说服效果的提升。
